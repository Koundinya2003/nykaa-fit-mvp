The hypothesis

Uncertainty about fit can reduce purchase confidence and drive size related returns. Personalised fit guidance may lift conversion while cutting those returns. Nothing in this build demonstrates that it does.

Not affiliated with Nykaa. Brand names and size charts are mock data so the catalogue reads realistically.

02 · confidence

Between two sizes? It says so.

score = completeness × (closeness × 0.5 + separation × 0.5)
  • completenessHow much of your body you told us. A ceiling, not a term to average in.
  • closenessHow well the winning size fits those measurements.
  • separationHow clearly it beats the runner up. A tie is a coin flip, not an answer.
  • Exactly between two sizes: separation near zero, so no size is named, however complete the profile.
  • Substituting a sold out size multiplies the score by 0.8.
  • Shoppers see High or Medium. Never a percentage: there is no validation data behind it.

04 · the experiment

Built to be measured, not to look good.

The business metric: the share of users who buy at least one wishlisted item within 30 days of saving it. A wishlist is a queue of unresolved questions, and “will this fit?” is the one that never resolves on its own.

Two arms

treatmentProduct page + Nykaa Fit (women's dresses)

TREATMENT_ALLOCATION is the only dial. Deterministic FNV 1a hash, so a visitor always lands in the same arm. Primary metric: product view to add to bag.

17 events, one pipe

Pluggable sinks, localStorage by default. registerSink() connects a real provider without touching a call site.

9 success metrics

    No body in the dataMeasurements never enter an event. A test checks every event the app can emit.
    No borrowed opinionsA test walks every engine file and fails on any import of the review corpus or a body estimator.
    No fake ratesThe Fit Lab withholds rates below a display floor: “1 of 1” is a count, never 100%.
    05 · honest scope

    What it is, what it is not, what it would need.

    Built with

    • React 19 + TypeScript, Vite 7
    • react router 7
    • Context state in localStorage
    • Hand written CSS, token layer
    • vitest unit tests
    • Generated SVG garments, 4 views each
    npm install
    npm run dev
    # localhost:5173

    Deliberately out of scope

    • Mock catalogue only, no live API, no backend
    • Checkout is review and confirm; no payment, no address
    • Sign in is visibly disabled, not dead
    • Size charts are plausible mock data, not real published charts
    • The engine is a heuristic, never calibrated on real purchases or returns
    • Guardrail metrics are named in the Fit Lab, not instrumented

    Production would need

    • Real brand size charts
    • Garment measurements
    • Historical orders keyed to size
    • Size specific return reason codes
    • Post delivery fit feedback
    • A powered A/B test
